AURA User Guide

Version 1.7 — Applied Unified Research Analytics

Introduction

AURA — Applied Unified Research Analytics — is a Python-native workbench for applied quantitative research — data analysis, statistics, and econometrics across economics, the social and policy sciences, survey work, and reproducible empirical studies. Its design draws inspiration in part from established statistical software — such as Stata — for an ergonomic, command-driven workflow, while AURA itself is an independent product built on the Python scientific stack: not a clone, and not tied to any single package.

It speaks the language that researchers already know: terse commands at a prompt, typed scripts that re-run end-to-end, named datasets in a workspace, and estimation tables that look right out of the box. Under the hood, every command runs on the modern Python scientific stack — pandas, statsmodels, scipy, matplotlib — so any AURA result is a step away from a Jupyter notebook, a publication-quality plot, or a CSV/Excel export.

AURA is built around four ideas:

  1. A concise command grammar. [prefix:] command [varlist] [if] [in] [weight] [, options] — the prefixes are by / bysort (the command for each group), quietly, capture, svy: and bootstrap:. Some commands also take the groups as an option: over() on summarize and graph bar, by() on egen, collapse and the density plots. Everything that should be one keystroke is one keystroke.

  2. A multi-dataset workspace. Several datasets can live in memory side-by-side under named aliases. merge, collapse, reshape, and append of Workspace datasets, add their result to the workspace as a new dataset — the original is never silently overwritten. (append using file, as in a do-file, adds the file's rows to the active dataset.)

  3. An extensible module protocol — .auru. Every command (regress, merge, egen, …) is a self-contained .auru Python file. Users and labs can drop their own modules into the search path without recompiling anything. Help files (.aurh) follow a minimal a small markup syntax — clean, scannable, never CSS.

  4. A real GUI that stays out of the way. Dialogs generate AURA commands you can copy, edit, save in a .aur script. The active dataset, the workspace, the variable list, and the command history are visible at a glance. Help and documentation open in an integrated viewer with a sidebar TOC, search, and tabs.

This guide walks through every user-facing command, from loading data to running a regression to producing a publication-grade graph. The companion Developer Guide covers writing your own .auru modules.

1. What is AURA?

AURA (Applied Unified Research Analytics) is a Python-native workbench for applied quantitative analysis — statistics, econometrics, and general data analysis. Its command interface is inspired in part by established statistical software such as Stata, but is built entirely on the Python scientific ecosystem (pandas, statsmodels, scipy, matplotlib) and is AURA's own design.

Purpose

AURA was designed to serve two distinct audiences simultaneously:

For the analyst / researcher (end user) The analyst does not need to know Python. They type short commands — summarize, regress, tabulate — and get immediate results, tables, and graphs. The interface is command-driven, repeatable, and scriptable, allowing full analytical workflows to be saved and re-run.

For the developer / methodologist AURA is a protocol and a platform. Developers write .auru modules in plain Python, using the bundled scientific stack (pandas, NumPy, SciPy, statsmodels, matplotlib) — or, running from source, any library you install — while interacting with the user's data and session through a clean, standardised API. A module becomes a new command the moment its file is placed in the right directory — no restart, no registration, no compilation.

The platform handles all the plumbing — parsing, session state, multi-dataset workspace, result storage, GUI refresh — so the developer focuses entirely on the statistical logic.

Design philosophy

Commands are short. Results are immediate. Modules are Python.

AURA does not try to replicate any existing package. It borrows selectively from the ergonomics of popular statistical software such as Stata (concise syntax, if/in/weight clauses, stored results r() / e()) while delegating all computation to the Python ecosystem and remaining fully open and extensible.

What AURA is not

  • A clone of any single package — AURA's design borrows selectively from popular statistical software (such as Stata), but its syntax, internals, and behaviour are its own
  • A programming language — AURA runs commands and Python modules
  • A substitute for Python — advanced users extend AURA through Python modules

2. Installation and Launch

Requirements

AURA ships as a self-contained installer for Windows — there is nothing else to install:

  • Windows 10 or 11 (64-bit).
  • No Python, no pip, no libraries. The installer bundles its own Python runtime and every scientific library AURA uses — pandas, NumPy, SciPy, statsmodels, matplotlib, Plotly.

Install and launch

  1. Download AURA-1.7-Setup.exe from the AURA website (the Download button) or the GitHub release, and run it — a per-user install, no administrator rights needed.
  2. Launch AURA from the Start-menu or desktop shortcut.

On a fresh PC, Windows may show a SmartScreen notice for a new, unsigned download — click More info, then Run anyway.

Running from source (for developers)

To run or extend AURA from the source tree instead, use Python 3.15 (the runtime the installer bundles) and install the library versions AURA is built and tested with, listed in requirements-lock.txt:

Numbers in tables

A number in a table takes at most 10 characters, in the format of its column. A longer one keeps fewer decimals, then turns to scientific notation with three significant digits (5.99e+15, 4.60e-31), so the columns never move. A number that is not 0 but would show as 0.000000 is written in scientific notation too, except in a column of four decimals or fewer (a p-value of 0.0000). display and esttab keep their own formats.

Links to the files written

A command that writes a file — esttab using, estimates table, export(), the saveres() and xls() options, graph save and graph export, save, export, log using — gives its full path in its message. Click the path to open the file: a Word or Excel file in its program, an html log in the AURA Viewer; a .aurg graph opens again in AURA (graph use).

4. Command Language

General syntax

command [varlist] [if condition] [in range] [, options]
Element Example Description
command summarize Command name (abbreviations allowed)
varlist wage educ exper One or more variable names
if condition if female == 1 Filter expression
in range in 1/100 Observation range (1-based)
, options , detail level(95) Options after the comma

Options syntax

, flag_option  valued_option(value)  numeric_option(3.14)
  • Flag options — presence means True: , detail, , noconstant, , force
  • Valued options — take an argument: , level(95), , by(region), , lines(50)

Common abbreviations

Full command Abbreviation(s)
summarize sum
tabulate tab
describe desc, d
regress reg
correlate corr
histogram hist
rename ren
use open
dir ls
erase rm, del
copy cp
frename mv, fren
mkdir md
rmdir rd
type cat
shell !
workspace ws

if conditions

summarize wage if female == 1
tabulate educ if age >= 25 & age <= 55
list if zone == 1 & size > 4

Every command reads its condition the same way, with the expression engine that generate uses:

  • A missing value never passes. Where wage is missing, wage != 0 is missing — not true — and the observation is left out. To select missing values, say so: if missing(wage) or if wage == .; if !missing(wage) keeps the others.
  • Scalars and functions can appear in a condition: if wage > k (after scalar k = 450), if substr(name, 1, 1) == "A".
  • A numeric variable alone is true where it is non-zero: if urban.

in range

Observation numbers are 1-based and count the whole dataset, before any if:

list in 1/10          first 10 observations
summarize in 50/100   observations 50 to 100
browse in 1/500       open browser showing first 500 rows
list in -10/-1        last 10 observations
summarize in 2/l      observation 2 to the last

f stands for the first observation, l for the last, and a negative number counts from the end (-1 is the last). The range must lie in the dataset — in i/j with i at least 1, j at least i and at most the number of observations — otherwise the command stops: r(198) "observation numbers out of range".

With both, in takes the observations first and if filters among them: list wage if female == 1 in 1/100 lists the women among the first 100 observations.

AURA reads the if and in of a command once, on the whole dataset, before the command runs: a mistake in the condition stops every command the same way (if: variable wage not found, r(111)). A command for which if or in has no meaning — describe, sort, display, rename… — refuses it: r(101) "if not allowed". With svy:, if and in define a subpopulation, like subpop(): the whole design stays for the standard errors. bootstrap: command if … draws among the selected observations only. if and in come before the comma: written among the options (summarize wage, detail if female == 1) they are refused, r(198).

Weights

A weight comes after if and in, in brackets: [aweight=w], [fweight=w], [pweight=w] or [iweight=w] (aw, fw, pw, iw for short). Each command accepts the weights that make sense for it; its help page says which. An observation whose weight is missing or zero is left out.

The weight may be an expression, computed for the command:

summarize pc_current_inc [aw=hhsize*sweight]     each household counted with its members
tabulate rururb [fw=hhsize*sweight]

A single name must be a variable: [aw=wt] with no variable wt stops the command, r(111).

5. Data Management

Loading data

Interactive (file dialog):

use

With a path:

use "C:\data\survey2024.aura"
use "C:\data\wages.dta"
use "C:\data\panel.csv"

Supported formats:

Extension Format
.aura Native AURA format (Parquet + JSON metadata)
.dta Stata dataset
.csv Comma-separated values
.xlsx / .xls Excel workbook

The .aura format

.aura is AURA's native dataset format. It stores the dataset (Parquet), variable labels, value label definitions, and survey metadata in a single compressed file.

Saving data

save
save "C:\data\survey2024.aura"
export csv
export csv "C:\data\wages.csv"
export excel
export excel "C:\data\wages.xlsx"

A name without an extension. save survey2024 writes survey2024.aura; use survey2024 reads survey2024.aura, or else survey2024.dta. Another extension writes that format: save "survey2024.dta" writes a Stata file. append using wave2 adds the file wave2.aura (or wave2.dta) to the active dataset, as in a do-file; with names of the Workspace only, append stacks them into a new dataset (Chapter 6).

Overwriting is guarded. Writing save, export or log using to a named file that already exists is refused unless you add , replace — so a dataset, an export or a log is never overwritten by accident. A bare save (re-saving the file the dataset is already tied to) is allowed; graph save follows the same rule.

Stata files. export stata "survey" (or export "survey.dta") writes a .dta in format 118 — the format of Stata 14 to 19, which every edition (BE, SE, MP) opens — with the variable and value labels. Format 119, readable by Stata/MP only, is used only for a dataset of more than 32,767 variables.

Generating and replacing variables

generate lnwage = log(wage)
generate young = (age < 30)
replace wage = wage * 1.1 if year == 2024
replace zone = 2 in 1/100

The , replace option on generate (and egen) lets a single command overwrite an existing variable — useful for re-running scripts without having to drop first:

generate lnwage = log(wage), replace          // re-running the same script: OK
egen wage_p75 = pctile(wage), p(75) replace   // overwrite previous wage_p75

If , replace is omitted and the target variable exists, the command aborts with a hint pointing to the option.

Types. A variable keeps one type, and replace (like generate … if) follows one rule:

  • numbers widen: an integer variable that receives 1.5 becomes decimal;
  • true/false values become 0/1: generate adult = (age >= 18) if !missing(age);
  • text stays text, and dates stay dates;
  • text and numbers do not mix: replace wage = "n/a" on a numeric wage is refused with a type mismatch error, and the variable is left as it was.

recode follows the same rule. Its text targets are written as text, without the quotes — recode region (1 = "north") (2/3 = "south") turns region into a text variable — and a numeric variable becomes text only when every non-missing value receives a text; otherwise the command is refused and says how many values are left without one.

Precision. An expression computes in double precision, whatever the storage of its variables: a float variable, or a short integer of a .dta file (byte, int, long), is read as a double, so that hhsize*sweight never overflows and x + 0.1 keeps its digits.

Extended generate — egen

egen extends generate with group statistics, ranks, and row-wise operations. It dispatches over a fixed library of functions:

egen newvar = function(args) [if cond] [, by(groupvars) p(N)]

Aggregation — collapse a single variable to a scalar (or by-group scalar):

egen wage_mean   = mean(wage), by(region)
egen wage_max    = max(wage), by(region year)
egen total_pop   = total(population)
egen wage_p75    = pctile(wage), p(75) by(region)
egen wage_iqr    = iqr(wage), by(region)

Available: mean, total, sum, sd, min, max, median, count, pctile, iqr.

Group helpers — within-group ordering and identifiers:

egen wage_rank   = rank(wage), by(region)      ascending rank within region
egen first_obs   = tag(person_id)              1 for first row of each person
egen first_yr    = tag(person_id year)         1 for first (person, year) combo
egen group_id    = group(region year)          1-indexed unique group id
egen seq_within  = seq(), by(person_id)        1, 2, 3 ... within each person
egen sn          = seq()                       1, 2, 3, ... over the dataset

Row functions — collapse across several variables for each observation:

egen rt          = rowtotal(x1 x2 x3)
egen rm          = rowmean(x1 x2 x3)
egen rmax        = rowmax(x1 x2 x3)
egen nonmiss     = rownonmiss(x1 x2 x3)         count of non-missing values
egen nmiss       = rowmiss(x1 x2 x3)            count of missing values

Available: rowmean, rowtotal, rowmax, rowmin, rowsd, rownonmiss, rowmiss.

Weights

egen and collapse accept a weight, which is applied to the statistics for which weighting is defined:

egen wage_mean = mean(wage) [aw=popwt], by(region)
collapse (mean) wage (sum) pop [aw=popwt], by(region)
Statistics
Weighted mean, sum / total, sd (and var in collapse), median and the percentiles, count
Not weighted min, max, iqr, the rank and group helpers (rank, group, seq, tag), and the row* family

The second series is not an oversight: a minimum is a value the data actually takes, and no weight changes which value that is. Asking for a weighted one is refused with a message naming the statistics that do accept a weight, rather than ignoring the weight in silence — a wrong number is worse than a refusal. Each command's help page lists its own set exactly. Both dialogs carry a Weights tab.

Notes: - egen refuses to overwrite an existing variable — pass , replace to overwrite (or drop it first). - if cond filters the rows that participate in the computation; rows excluded by if get NaN in the new column. - Use the dialog Data → Variables → Extended Generate (egen)… to build commands interactively.

Converting and checking variables

encode  strvar, gen(numvar)     text → numbered categories, keeping the text
                                as value labels
decode  numvar, gen(strvar)     the reverse: labels → a string variable
destring strvar, replace        text that holds numbers → a numeric variable
tostring numvar, replace        numeric → text

encode/decode are the pair to reach for when a categorical variable arrives as text: encode makes it usable in i. factor notation and in tabulations while keeping the original wording visible as labels.

Two commands check rather than change the data:

assert wage >= 0                 stop the script if the claim is false
assert age < 120 if !missing(age)
contract region sex              replace the data by the counts of each
                                 combination, in a variable named _freq

assert is what turns an assumption into something the script enforces: it does nothing when the claim holds and stops with an error when it does not, which is exactly what you want in the middle of a long pipeline.

Creating small test datasets — input, set obs, set seed

For interactive exploration or quick test datasets without loading a file:

set obs N — empty dataset of N rows

clear
set obs 100

If a dataset is already loaded, set obs N extends it to N rows (new rows are NaN); the count cannot shrink (use drop in N+1/last instead).

set seed N — reproducible random numbers

set seed 42

Affects both numpy and Python's random module, so any subsequent simulation is reproducible.

input ... end — inline data entry

In a .aur script, write a multi-line block:

clear
input id wage age
1 10 25
2 20 30
3 30 35
end

Rules: - The line input varname1 varname2 ... declares the columns. - Each subsequent line is one row of values, separated by whitespace. - end (alone on its line) closes the block. - Quoted strings are supported: 1 "John Doe" 30000. - A missing value is written . - Column types are inferred per column (int, float, or str). - Comments (*, //) inside the block are ignored.

The dataset created replaces any existing one — use clear first to start fresh.

Preserving and restoring the dataset — preserve / restore

preserve snapshots the current dataset (data + variable labels + value labels + notes). A subsequent restore rolls back to that snapshot. Typical use case:

preserve
keep if female == 1                  // explore a subset
summarize wage
regress wage age educ
restore                              // back to the full dataset
Command Effect
preserve Snapshot current dataset state. Overwrites any previous snapshot.
restore Replace the active dataset with the snapshot. One-shot (the snapshot is consumed).

A restore without a prior preserve returns an error.

compress

Finding and removing duplicates — duplicates

duplicates reports, lists, tags or drops observations that are identical over a variable list (or the whole row when none is given):

duplicates report            how many rows are duplicated
duplicates examples          one example row per duplicated group
duplicates list              show all the duplicated rows

Merging datasets — merge

merge combines several workspace datasets via an outer join on shared keys. No file paths are accepted — all datasets must already be loaded into the workspace. This keeps merge fast and predictable.

Syntax

merge {1:1 | 1:m | m:1 | m:m}  [keyvars]  using <alias1> [<alias2> ...]  [, options]

If keyvars is omitted, the datasets are merged by observation number (row position) — a positional merge, pairing the first row with the first, the second with the second, and so on. This is the default rule whenever no key is supplied:

merge 1:1 using wave2                merge by row position (no key)

Examples

use "wave1.aura"                  → workspace alias 'wave1'
use "wave2.aura"                  → workspace alias 'wave2'
use "wave3.aura"                  → workspace alias 'wave3'

merge 1:1 hh_id using wave1 wave2                       2-way merge, wave1 is prior
merge 1:1 hh_id using wave1 wave2 wave3                 3-way merge, wave1 is prior
merge 1:1 hh_id year using panel1 panel2                multi-key merge
merge m:1 region using households regions               many-to-one (lookup table)

Reporting by group — over()

Percentiles and quantile groups — pctile, xtile, _pctile

_pctile leaves the percentiles in r(r1), r(r2)…; pctile writes them in the first observations of a new variable (here the nine cut points of the deciles); xtile gives each observation the number of its group. The weight chooses the population: [aw=sweight] gives quintiles of households, [aw=hhsize*sweight] quintiles of individuals. An observation at a cut point goes to the lower group, so that a group cut whole weighs about a fifth, not exactly. With proportions, xtile gives instead the share of each observation in each group, and the groups weigh exactly a fifth:

Panel data — xtset / xtreg

Panel (longitudinal) data follow the same units over several periods. Declare the panel identifier with xtset, then estimate with xtreg:

xtset firm year
xtreg profit size rd
xtreg profit size rd, fe
xtreg profit size rd, be
xtreg profit size rd, re vce(robust)

xtset panelvar [timevar] records which variable identifies the panels (and, optionally, time). xtreg depvar indepvars [, re|fe|be] then fits:

  • re, the default — random effects (GLS): treats the unit term as random and uses within and between variation — more efficient when that term is uncorrelated with the regressors. theta reports the GLS weights.
  • fe — fixed effects (within): keeps only the variation within each unit, sweeping out anything constant about it (sector, location) so it cannot bias the slopes.
  • be — between effects: the regression on the units' means (wls weights each unit by its number of observations).

Under the table, re and fe show sigma_u (the standard deviation of the unit effects), sigma_e (that of the idiosyncratic error) and rho (the share of the variance due to the unit effects); fe adds the F test that all unit effects are zero. To choose between fixed and random effects, store both and run the Hausman test:

quietly xtreg profit size rd, fe
estimates store fixed
quietly xtreg profit size rd, re
hausman fixed .

A large chi2 says the random-effects assumption fails. The estimators, the variance components and the Hausman test are those of the linearmodels library.

Two more estimators, and two more kinds of standard errors:

xtreg profit size rd, mle                             random effects, maximum likelihood
xtreg profit size rd, pa                              population-averaged
xtreg profit size rd, fe vce(cluster region sector)   two-way clustering
xtreg profit size rd, fe vce(dkraay bartlett 2)       Driscoll-Kraay
  • mle — random effects estimated by maximum likelihood (the mixed model of statsmodels), with the likelihood-ratio test that sigma_u is zero; sigma_u, sigma_e and rho come without standard errors. No weights, no vce().
  • pa — the population-averaged model: GEE with the same correlation between any two observations of a unit (statsmodels); vce(robust) gives the sandwich estimator. No weights.
  • vce(cluster v1 v2), with fe — standard errors robust to correlation within the groups of either variable; each panel lies within one group of each.
  • vce(dkraay kernel [#]), with fe — Driscoll-Kraay standard errors, robust to correlation across the panels and over time; the kernel is bartlett, parzen or quadraticspectral, # the number of lags (by default the number of periods minus 2). The time variable must be declared.

After xtreg, predict gives xb (the default), stdp, ue (the combined residual), u (the unit effect), e (the idiosyncratic error) and xbu (xb plus u) — u, e and xbu on the estimation sample only; after pa, mu (the default), rate, xb and stdp. test and lincom use e(b) and e(V): an F test (t) after fe and be, a chi2 (z) otherwise.

predict uhat, u
test size rd
lincom size + rd

indepvars accept the same factor syntax as regress (i.var, 2.var, c.x#i.g, c.x##i.g, c.age#c.age). Options: i(panelvar) (name the panel inline; overrides xtset), t(timevar), vce(robust) (cluster by panel) / vce(cluster v [v2]) / vce(dkraay kernel [#]) (not with be), level(#), [aweight=var], [pweight=var], [fweight=var] (not with be). Any other option is refused.

Instrumental variables — ivregress

When a regressor is endogenous (correlated with the error — chosen jointly with the outcome, measured with error, or a proxy for something unobserved), OLS is biased. ivregress uses an instrument — a variable that moves the endogenous regressor but has no direct effect on the outcome:

ivregress 2sls wage educ (exper = age tenure)
ivregress gmm  wage educ (exper = age tenure), vce(robust)

ivregress estimator depvar [exogvars] (endog = instruments) [, options] with estimator = 2sls, gmm or liml. The exogenous regressors come first; the parenthesised part lists the endogenous regressor(s) = the excluded instruments. Options: vce(robust) / vce(cluster v), noconstant, level(#), [aweight=var]. Below the coefficients it prints an Instrument diagnostics block (weak-ID Cragg-Donald Wald F and the standard IV tests) so you can judge whether the instruments are strong. Estimation is delegated to the linearmodels library.

Resampling — bsample

bsample [N] replaces the data in memory with a sample of N rows drawn with replacement (default: the current N) — the building block of a bootstrap. Options: strata(varlist), cluster(varlist), idcluster(newvar), svy (use the survey design). Wrap it in preserve / restore, or drive it from the bootstrap prefix, which resamples and re-estimates for you.

Margins (graphregion(margin()), plotregion(margin())): zero vsmall small medsmall medium medlarge large vlarge huge — or any number.

Legend positions (clock face, 1-12):

              11   12    1
        10                    2
         9                    3
         8                    4
              7    6    5

By default the legend is in the plot, where it hides the fewest points. In the plot (ring(0)), the clock points to a corner or a side: 11 and 10 the top left corner, 12 the top, 1 and 2 the top right corner, 3 the right side, 4 and 5 the bottom right corner, 0 the centre. Outside (ring(1)): above the plot (11 12 1), on its right (2 3 4), below it (5 6 7) or on its left (8 9 10).

Texts, legend, axes, regions and objects added

Texts. A title, a subtitle, a note, a caption and the axis titles take sub-options after a comma: their size and colour, their place, a box.

scatter wage educ, title("Wages and schooling", size(large) color(navy)) subtitle("Survey 2024")
scatter wage educ, title("Wages" "by years of schooling")          two lines
scatter wage educ, title("Wages", pos(11)) note("Source: survey", pos(5))
scatter wage educ, title("Wages", box fcolor(gs14) lcolor(navy) rounded)

pos() picks a standard place: above the plot at the left (11), centre (12) or right (1); a note or a caption at the foot, left (7), centre (6) or right (5); an axis title along its axis. at(x y) puts the centre of the text anywhere, in fractions of the graph from its bottom-left corner: title("Wages", at(.25 .9)).

The room of the plot. The plot takes the room that the texts and the legend leave it. A part moved to a free place gives its room back; outside the plot it takes room where it is, on the plot it is drawn over it. A larger text takes more room. noroom draws a part over the plot wherever it is; room makes the plot leave room for it even when it sits on it.

Greek letters and symbols. Any text of a graph accepts matplotlib's math notation between dollars:

scatter wage educ, title("Effect of $\beta_1$ on $y^2$")

$\alpha$, $\sigma^2$, x$_{i}$, $\leq$, $\sum$ … In the Graph Editor, the α button beside a text composes them (see The Graph Editor below).

Legend.

twoway (scatter wage educ) (lfit wage educ), legend(order(1 "Workers" 2 "Fit") pos(11) ring(0) cols(1))
twoway (scatter wage educ) (lfit wage educ), legend(pos(6) ring(1) rows(1) region(lcolor(none)) title("Series", size(small)))

order() sets which entries show, in which order, and their texts. ring(0) puts the legend in the plot, ring(1) outside it, on the side pos() points to; at(x y) is a free place. region() is its frame: its fill, its outline (lcolor(none): no frame), its margin, rounded corners.

Axes.

scatter wage educ, xlabel(8(2)20, format(%9.0f) labcolor(gs6) nogrid) yscale(log) ymtick(#4)
scatter wage educ, xlabel(10 "Primary" 14 "Secondary" 18 "University") xscale(reverse)

xlabel() says where the labels go — about n of them (#6), values (0(10)100), or values with their texts — and how they look; its options also set the ticks and the grid. xscale() takes log, reverse, alt (the other side), off and noline. The same options exist for y and for the right axis (y2label(), y2scale()).

Regions.

scatter wage educ, graphregion(fcolor(gs15) margin(5 5 8 5)) plotregion(lcolor(black) margin(5))

The graph region is the whole graph; four numbers in its margin() fix the space around the plot (left, right, bottom, top, in % of the graph). The plot region is the plot: lcolor() draws its frame, margin() sets the space between the data and that frame.

Objects added. A text, a line or an arrow at points of the data — y, then x, as on the axes:

scatter wage educ, text(65 16 "Graduates", placement(e) color(maroon)) addline(15 12 70 12, lpattern(dash)) addarrow(60 10 52 15, lcolor(navy))

Repeat text(), addline() or addarrow() for objects of different looks. They never change the range of the axes. help twoway documents every sub-option.

Saving and editing graphs (.aurg)

Any AURA graph can be saved to an .aurg file and reopened later to view or edit. An .aurg is not a picture — it is a small, self-contained recipe: the command that drew the graph, plus the data columns it used, frozen inside the file. Reopening re-runs that command over its own frozen data, so a saved graph is independent of your current dataset and always redraws the same figure.

Editing a graph on screen — Start Graph Editor. Each graph window holds one graph of the session (Graph 1, Graph 2…), with the data it was drawn from frozen at that moment: later changes to the dataset do not touch it. For the types the editors know, its toolbar has a Start Graph Editor button. The window gives way to the graph's editor, opened at the same place with the graph at the same size; close the editor and the edited graph comes back in its window. Closing a graph window closes that graph for good, and clear all closes every graph.

Saving.

histogram exppc, normal
graph save "spending.aurg"           write the current graph
graph save "spending.aurg", replace  overwrite an existing file
graph use  "spending.aurg"           redraw it later, from its frozen data

graph save writes the current graph — the last one drawn or edited — with its edits. The graph window's toolbar save (disk) icon also offers .aurg as its default format, alongside PNG / PDF / SVG, for that window's graph: the image formats save the picture, .aurg saves the editable graph.

Editing — File → Open Graph. Opening an .aurg routes it to the editor its type calls for. Each editor works on the graph's own frozen data (never the current workspace), shows a live preview, and saves back to .aurg:

Graph Editor
Pie Pie editor — category / value / nested, a palette template and a colour per slice, donut, labels, %
Histogram Histogram editor — bins, y-axis type, normal & kernel density overlays, colours
Density / CDF (kdensity, cdfplot) Density or Cumulative Distribution editor — variables to compare, by() group, weight, bandwidth / x range / points (density), a colour, pattern and width per curve
Bar (graph bar / hbar) Bar editor — statistic, variables, over() / then-by, weight, orientation, stacked / percent, value labels, a palette, and a fill, intensity, outline and outline width per series
twoway / scatter / line / area / range 2-D Graph editor — one editable object per plotted series, with axes / legend / titles

The editors work in the same way: see The Graph Editor below. help graph documents the whole feature.

Raw matplotlib — graph mpl. For a plot the graph commands don't cover, graph mpl <python> runs your own matplotlib on the active dataset, with every column bound to its bare name (plus df, plt, np, and a ready fig / ax):

graph mpl ax.scatter(exppc, exp, c=zone, cmap="viridis")
graph mpl ax.hist(exppc, bins=40); ax.set_xlabel("Spending")

The figure shows like any AURA graph and saves to .aurg. It is the escape hatch to matplotlib's full power; for reusable, AURA-styled graphs use the graph commands or a module. For a multi-line script (helper functions, many statements), keep it in a .py file and run graph mpl using "script.py" — a dataset is optional, so pure matplotlib runs too.

The Graph Editor

Opening it. The Start Graph Editor button of a graph's window, or File → Open Graph (an .aurg file). The editor shows the graph in the centre, as its window will draw it; on the left the Quick Options panel — the data (variables, if/in, the weight, the plot types) and the options changed most often (titles, legend, ranges, colours); on the right the Objects tree, every part of the graph: titles, the plot region with its plots and their curves, the axes, the legend, the notes, the objects added. Its toolbar shows or hides the two panels, adds a text, a line or an arrow, and closes the editor.

With the mouse.

  • A part under the mouse is outlined; a click selects it (the Objects tree follows, and the other way round).
  • Drag a part to move it anywhere in the graph; hold Shift as you drop it to put it at the nearest standard place instead.
  • Drag the edges or the corners of the selected plot region to resize the plot.
  • Double-click a part — on the graph or in the Objects tree — to open its window.
  • A right click gives the part's menu: its properties, its standard place again, and for the plot region Fit the Plot to the Free Room and Make Room for Moved Parts.

A window for each part. Each part has a window of its own options: a text (its lines, font, size, colour, box, place), the legend (its entries, layout, text, title, frame, place), an axis (scale, labels, ticks, grid, line), a region (fill, outline, margins), a curve (by its type: markers, point labels, line, fill and outline, bars, the fit, the slices of a pie), an object added. What you set is written at once and the graph is drawn again; Cancel puts back what was there when the window opened. A colour left empty shows, with the word auto, the colour the graph is drawn with. A part not drawn yet (a subtitle, a caption, the legend of a single curve) has a grey row in the Objects tree: double-click it to add it. The Quick Options panel and the windows always show the same values.

Objects added. Add Text, Add Line and Add Arrow on the toolbar: click where the text goes; draw a line or an arrow with the button held from one end to the other (Esc: no more). They are written as text(), addline() and addarrow(), and are moved, edited and deleted like the other parts.

Symbols. The α button beside a text field opens Insert Symbol: Greek letters, operators, large symbols and structures (exponent, index, fraction, root, accents). The expression is composed apart, with its own preview; Insert writes it at the cursor, between dollars.

Everything is written in the command. Each gesture becomes an option of the graph's command, so the edited graph is saved as .aurg, drawn again by its command, or copied as code (Copy the Graph's Code in the right-click menu of its window). An editor changes only what you edit: anything it does not show stays as written, and a curve keeps its style by what it draws (removing a variable takes its colours with it).

The graphs of the session

Each graph drawn is a graph of the session, numbered Graph 1, Graph 2…

graph list                                   the graphs in memory: number, state, command
graphmerge -2 -1, cols(2) title("Two views")   the last two graphs in one figure
graph export "fig.emf"                       the current graph as a picture
graph clear                                  close every graph; numbering starts again at 1
  • One window for all the graphs. set wingraph on puts the new 2-D graphs in a single Graphs window, one under the other (the newest on top, or at the bottom with set wingraph on, bottom), each with its own toolbar; set wingraph off gives each graph its own window again. The setting is kept for the next sessions.
  • Merging graphs. graphmerge draws several graphs in one figure: see Merging graphs below.
  • Closed graphs. Closing a graph's window closes that graph. After graph mem on, a closed graph stays in memory, hidden, so graphmerge can still take it.
  • Copying a graph. The right-click menu of a graph puts it on the clipboard as a picture (PNG, JPEG), as a vector drawing (SVG, or EMF for Word and PowerPoint), or as the commands that draw it again (Copy the Graph's Code).
  • Exporting. The save icon of a graph's toolbar writes .aurg (the editable graph) or a picture; graph export "file" writes the current graph as a picture, PNG, PDF, SVG or EMF by the file's extension.

Merging graphs — graphmerge

graphmerge draws several graphs of the session in one figure, in a grid. Each graph is drawn again from its own command, its frozen data and its edits — a vector drawing, not pasted pictures — and the figure is a graph of the session like the others: it is saved as .aurg, exported, copied, and merged again. In a new session, the four graphs below are Graphs 1 to 4:

histogram exppc if exppc < 300000
twoway scatter exppc size
graph bar (mean) exppc, over(zone)
kdensity exppc if exppc < 300000
graphmerge 1/4, title("Household spending") note("Source: bkf98I")
graphmerge 1 2 3, rows(1)              one row
graphmerge 1 2 3, cols(1)              one above the other
graphmerge 1 2 3, holes(2)             a 2 x 2 grid, its second place empty
graphmerge 5 4, cols(1)                the figure of four (Graph 5) over a graph

Which graphs. By number (graph list shows them): 1 3 4, a range 1/4, a negative number counted from the last graph (-1 the last, -3/-1 the last three), or _all. A graph whose window was closed can still be taken after graph mem on.

The grid. About square by default; rows() or cols() set it, colfirst fills it column after column, holes() leaves places empty. imargin() sets the margin around each graph: zero, tiny, small (the default), medium, large, or a percentage.

One scale. ycommon and xcommon give the graphs of the type of the first one the same y and x scales, so that they compare at a glance:

histogram exppc if exppc < 300000 & zone == 1, title("Rural")
histogram exppc if exppc < 300000 & zone == 2, title("Urban")
graphmerge -2 -1, cols(1) ycommon xcommon

A size for a page. The figure takes the width of a page's text (6.5 inches) and keeps each graph in the proportions of a graph window: one row of three graphs is a strip 1.4 inches high, two rows of two half a page (4.1 inches), three graphs one above the other a full page (9 inches). A merged figure placed in another keeps its own proportions: the figure of four over a graph takes nearly the whole page, the four on its upper half. Text and markers shrink with the graphs; xsize(), ysize() and iscale() set them yourself. In a small graph, long axis labels pass to scientific notation and labels that would touch are thinned out.

Titles, scheme, file. title(), subtitle(), note() and caption() belong to the whole figure; scheme() or commonscheme draws every graph with one scheme; saving("figure.aurg", replace) also saves the figure.

From a dialog box, and as code. Graphics → Merge Graphs... lists the graphs in memory and writes the command; the Graphs window of set wingraph on has a Merge... button. Copy the Graph's Code, in the right-click menu of the figure, gives the commands that draw it again: those of its parts, then the graphmerge that joins them. A merged figure has no editor of its own: edit a part, then merge again.

13. Scripting with .aur Files

A .aur script is a plain text file with one AURA command per line.

Script syntax

// This is a single-line comment
* This is also a single-line comment

/* This is a block comment
   that can span several lines.
   Useful for headers, notes, and disabling code. */

use "C:\data\survey.aura"
sort weight
summarize exppc
regress exppc size zone, robust
tabulate zone

Line continuation

Use /// to continue a long command on the next line:

regress exppc size zone ///
    age female, robust level(90)

Inline comments

sort weight   // sort ascending before listing
list in 1/10

Delimiter switching — #delimit

By default, AURA treats each newline as a command terminator. Inside a script you can switch to semicolon-terminated commands — useful when a single command spans many lines:

#delimit ;
regress wage age educ exper region
    if year == 2024,
    robust
    cluster(region) ;
summarize wage age educ ;
#delimit cr
describe
Directive Meaning
#delimit cr Newline-terminated (default)
#delimit ; Semicolon-terminated; newlines become whitespace

Comments (*, //, /* */) and line continuation behave the same in both modes.

Control flow and macros

A .aur script can use control structures and macros for any non-trivial workflow (loop over years, datasets, or specifications; build varlists dynamically; compute and pass scalars). The script editor detects these keywords and routes the script through the AurRuntime interpreter automatically — no separate command, no do prefix.

Macros and scalars

local mylist "wage age educ"          // text macro
local n = 10                          // numeric (still stored as text)
local n = `n' + 1                     // expression on the right-hand side
scalar k = 1.96                       // floating-point scalar (used in expressions)
scalar threshold = k * 0.05
  • Reference a local macro with backticks-and-apostrophe: `mylist'
  • Reference a scalar by its bare name inside an expression: n * k + 1
  • Macros nest: local greeting "Helloname'"`
  • The right-hand side of = is an expression, with all of AURA's functions (help functions). One that cannot be computed is an error, never an empty macro.
  • `++i' adds 1 and gives the value; `*' gives all the numbered macros; c(N), c(k), c(os), $S_DATE give values of the system. See help macro.

Loops

forvalues i = 1/5 {                   // 1, 2, 3, 4, 5
    use "wave`i'.aura"
    summarize wage
}

forvalues i = 2(2)10 {                // 2, 4, 6, 8, 10  (step = 2)
    summarize x`i'
}

forvalues i = 10(-1)1 {               // 10, 9, ..., 1
    display "Year `i'"
}

foreach v of varlist wage age educ {  // iterate over a literal varlist
    summarize `v', detail
}

foreach v of local mylist {           // iterate over a previously-defined local
    regress wage `v', robust
}

foreach n of numlist 1 3 5 10 100 {
    summarize x in 1/`n'
}

foreach w in North "South coast" {    // any words
    display "`w'"
}

foreach r of levels region {          // the values of a variable
    count if region == `r'
}

foreach v of newlist z1 z2 {          // names that must be free
    gen `v' = 0
}

continue goes on to the next round, and continue, break leaves the loop. See help foreach, help forvalues, help while.

Conditionals and while

if `n' > 5 {
    display "Many observations"
}
else {
    display "Few"
}

while `n' > 0 {
    display "`n' iterations left"
    local n = `n' - 1
}

On one line, and with several cases:

    display "A"
}

    display "B"
}

display — printing to the console

display "Hello world"
display "Iteration " `i' " of " `N'
display "wage * 2 = " `wage_obs' * 2          // expressions are evaluated

display "mean: " %9.2f 1234.5678
display "name" _col(12) "value"
display _dup(20) "-"

Putting it together — typical economic workflow

* Sensitivity analysis: re-run a regression across multiple waves and controls
local controls "age educ exper"
local outcome "wage"
scalar alpha = 0.05

forvalues year = 2018/2024 {
    use "wave`year'.aura"
    summarize `outcome', detail
    if `year' >= 2020 {
        foreach v of local controls {
            regress `outcome' `v' if region == 1, robust
        }
    }
    display "── Wave `year' done (alpha = " alpha ") ──"
}

Caveats and limits

  • Block syntax requires the opening { at the end of the header line: forvalues i = 1/10 { — not on a separate line.
  • In the condition of while and if, a number that is not 0 is true and a missing value is false. &, | and ! are and, or, not.
  • A variable in such a condition counts by its first observation. To test every row, use count if.
  • In the window, the Stop button ends a loop that does not stop by itself.
  • AURA's existing if clause (summarize x if x > 0) is unrelated — that's a per-command filter and works exactly as before.

Python blocks — py: ... end py

A py: block runs raw Python inside an .aur script, with every column of the active dataset bound to its bare name (a numeric array). It is AURA's escape hatch for anything the built-in commands don't cover: AURA is Python-native, so you drop straight into Python and back without leaving your workflow. Like forvalues, it is a script construct — it spans several lines, so it lives in a script or the Script Editor (or is pasted, lines and all, into the command box).

py:
    z = exppc * 2            # exppc is a column -> available by its bare name
    df["z"] = z              # put it back -> kept when the block ends
end py

Inside the block you have every variable of the active dataset (as a numpy array), the whole dataset df, np and pd, and an aura bridge back to AURA. Comments use Python's #.

Keeping a variable — the data contract. A value you compute is kept only if you put it back. df["z"] = ... adds a quick, bare column; for a first-class AURA variable (with a label and a display format), use aura.set_var:

py:
    import numpy as np
    aura.set_var("logexp", np.log(exppc), label="Log spending", format="%9.3f")
end py

When the block ends, AURA adopts whatever df now holds — edits in place, a rebind, new or dropped columns, added rows — and surviving columns keep their labels. A value computed but never put back simply vanishes at end py.

The aura bridge is deliberately narrow — it does not turn into a second language:

Call What it does
aura.run("gen z = exppc*2") run any AURA command from Python (labels, formats and the Review trace all apply)
aura.set_var(name, values [, label=, format=]) add or replace a labelled, formatted variable
aura.scalar(name, value) post a scalar into AURA's namespace
aura.getvar(name) a column as a numpy array

Prefer aura.run / aura.set_var for data you want to keep and trace; a bare df[...] = ... is for scratch. Don't reimplement gen / egen in Python — call them through aura.run.

Output and errors. Anything the block prints appears in the Results window. A Python error is reported with the offending block line; turn on set tracedeep on for the full Python traceback. When you run a script from the Script Editor, errors are listed in its Problems panel (with a line number to jump to), which keeps the Results window for real output. help py documents the block.

16. Survey Data Analysis

AURA estimates population quantities from complex-survey data using Taylor-linearized (linearization) standard errors, the default for the svy: prefix.

Declaring the design

svyset psu [pw=weight], strata(strata) fpc(fpc)
svydes

svyset records the sampling weight, PSUs/clusters, strata and an optional finite-population correction. svydes describes the declared design. When a .dta file already carries an svyset design, AURA imports it automatically on use (and via File ▸ Open Data). See help svyset, help svydes.

Survey estimators

svy: mean income food
svy: total income
svy: ratio food/income
svy: proportion sex
svy, subpop(urban): mean income
svy, level(90): mean income

Each posts e(b) (point estimates), e(V) (the full covariance matrix), e(names) and e(df_r) (design df = #PSUs − #strata). See help svy.

Groups: over(), quantile groups and wover()

over(varlist) gives one estimate per group of categorical variables, each group a subpopulation (the whole design kept), with the covariance between the groups in e(V):

svy: mean wcorn, over(rururb)

Quantile groups (quartiles, quintiles, deciles) are made by xtile. Cut whole, a group weighs only about a fifth: the household at a cut point goes wholly to one side. With the option proportions, xtile gives instead the share of each observation in each group — 1 or 0, a fraction for the observations at a cut point — so that each group weighs exactly a fifth. The share variables form one categorical variable, saved with the data, that wover() takes. The weight chooses the population: [aw=sweight] gives quintiles of households, [aw=hhsize*sweight] quintiles of individuals (a weight may be an expression). On the Mexican cereals of the help (auru/data):

use "data/mexico_2014_cereals.dta", clear
xtile q = pc_current_inc [aw=hhsize*sweight], nquantiles(5) proportions
gen double wind = hhsize*sweight
svyset psu [pweight=wind], strata(strata)
svy: mean pc_current_inc, wover(q)
svy: mean wcorn, over(rururb) wover(q)
svy, subpop(q == 1): mean wcorn

The second line crosses the areas and the quintiles; the third estimates on the first quintile alone.

Standard errors. The cut points of the quintiles are estimated: another sample would give other cut points, hence other groups. wover() and subpop(q == k) take it into account (the influence function of the quantile, Beach and Davidson 1983); wover(q, fixed) takes the cut points as given, as a categorical over() does. The mean income per head by quintile of income per head:

Quintile Mean Std. err., cut points fixed Std. err., cut points estimated
1 1,016.6 10.5 17.5
2 1,746.3 5.6 19.9
3 2,496.3 6.4 27.2
4 3,773.0 12.0 47.9
5 10,725.4 478.3 516.8

A bootstrap of the design that ranks the data again in every replication gives 15.3, 19.2, 26.2, 45.2 and 518. The difference does not fade in a larger sample: the error on a cut point, like the error on a mean, falls with the square root of the sample size. It is large when the variable follows the ranking near the cut points — the income of a narrow middle quintile moves with its bounds — and nil when it does not (the age of the household head, whose standard errors do not change). Groups defined by a known threshold (a poverty line given in advance, an area) have no cut point to estimate.

Groups of the estimated variable itself — nquantiles(). svy: mean y, nquantiles(5) makes the five groups of exactly equal weight of y itself, ranked with the weight of the design, and gives the mean of each: no xtile, and the correction for the cut points is exact. units(var) counts each observation var times (the people of a household, adult equivalents, hectares): the weight of the design is multiplied by var for this estimation alone. The quintiles of individuals above, from the design of the households:

svyset psu [pweight=sweight], strata(strata)
svy: mean pc_current_inc, units(hhsize) nquantiles(5)
svy: ratio hh_current_inc/hhsize, nquantiles(5)

The two estimations give the same estimates and standard errors as wover(q) above: a ratio is ranked by the ratio of each observation, weighted by its denominator. dec(#) sets the number of decimals of the table. In the dialog box (Statistics > Survey Data Analysis), the tab Over offers the three kinds of groups: categorical variables (over()), group weights (wover()) and groups of the variable itself (nquantiles()).

pctile and _pctile give the percentiles themselves; see help pctile.

Nonlinear combinations — nlcom

nlcom computes a (possibly nonlinear) function of the posted estimates with a delta-method standard error (numeric Jacobian):

svy: mean food income
nlcom (share: food/(food+income))
nlcom (food/income - 1)^2

Nonlinear expressions of survey means — nlexp

nlexp estimates a function of the survey means of variables, in one line. Mark the per-observation transform with mean(...), brackets [...], or Mata-style colon operators (:* :/ :^) — the three are equivalent:

svy: nlexp food/size                              // = mean(food)/mean(size)
svy: nlexp mean(size*(z-exppc)/z) / mean(size)
svy: nlexp [size*(z-exppc)/z] / [size]
svy: nlexp (size :* (z-exppc) :/ z) / size, expname(gap)

See help nlcom, help nlexp.

17. Macros, Scalars and Matrices

AURA provides macros, scalars and (numpy-backed) matrices, usable at the console and in .aur scripts.

Local and global macros

local controls "age educ exper"
regress wage `controls'
global pl = 80000
gen poor = exppc < $pl

A local (local name …, referenced `name') belongs to its script or module; at the console it stays from one command to the next. A global (global name …, referenced $name or ${name}) persists for the session. Assignment distinguishes text from value: local x "2+2" stores the text, local x = 2+2 stores the result; local ++i increments. See help local, help global.

Scalars

scalar z = 80000
display "poverty line = " z
gen poor = exppc < z

A scalar is a persistent number, referenced by its bare name inside any expression. See help scalar.

Extended macro functions

local k : word count `controls'
local first : word 1 of `controls'
local u : list uniq mylist
local t : type wage
local lab : variable label wage
local txt : label sexlbl 1

They read the attributes of variables and work on lists and texts: word count, word # of, list (uniq sort dups first last rest reverse join filter prefix suffix posof == === in), subinstr, length, piece, copy, display, all, dir, variable/value label, label, type, format. See help macro.

A macro never defined gives nothing, and the Problems panel warns about it in a script. With set strictmacros on it is an error, r(111).

Temporary names

tempvar, tempname and tempfile create unique throw-away names that are cleaned up when the program/script ends.

Writing a text — "…", `"…"', ¨…¨

display "plain text, macros replaced: `n'"
display `"it may hold "double quotes", macros replaced: `n'"'
display ¨exact: "quotes", `n', $x and {hline 5} stay as they are¨

¨…¨ is exact: nothing in it is replaced, and it may run over several lines. On a French keyboard, press the ¨ key, then the space bar. Inside quotes everything is text, // and /// included: to write a long text on two lines, close it and join two texts, with + in an expression:

display "first part " ///
        "second part"
gen s = "first part " + ///
        "second part"

A double quote never closed is an error, r(198). To show a macro that holds quotes, write display `"`x'"' or display `x:q'. See help quotes.

Reading a text — tokenize, gettoken

tokenize "2021,,Dakar", parse(",") clean      // `1' 2021, `2' empty, `3' Dakar
tokenize "2021,Dakar", parse(",") clean into(year city)
gettoken first rest : mylist                  // the first word, and the rest

Testing before acting — confirm, capture

capture confirm variable income
if _rc != 0 {
    generate income = wage * 12
}

confirm checks a variable, a new name, a number, a file, a matrix or a scalar, and fails with a return code a script can read. After capture, _rc holds the code and _rcmsg the message. error # stops a script with a chosen code. unab writes out a list of variables in a macro, and numlist a list of numbers.

Matrices — Mata-style, without mata:

Matrices are numpy arrays (fast, no size limit). You operate on them with ordinary command lines:

matrix A = (1,2 \ 3,4)             // , = columns, \ = rows
matrix X = data(educ exper)        // data columns -> matrix
matrix y = data(wage)
matrix beta = invsym(X'*X)*X'*y    // OLS by hand; ' = transpose, * = product
matrix V = e(V)                    // pull a posted result
matrix C = A[2, .]                 // 1-based indexing; '.' = whole dim
matrix list beta
svmat beta, names(b)               // matrix -> variables

Operators: ' * + - :* :/ :^ ^ \ , [i,j]. Functions: I J inv invsym rows cols trace det diag cholesky eigenvalues. The data bridge accepts if/in: data(inc, in(1/100) if(inc<1000)). Loops use AURA's own forvalues/foreach. See help matrix.

Stored-result commands — return, ereturn, sreturn

Every command leaves results behind: r() for descriptive commands, e() for estimators, s() for settings. Inspect and post them with:

  • return list / return dir — show the active result set / list the archive.
  • return scalar name = exp, return matrix name = M — post an r-class result.
  • ereturn list / ereturn scalar name = exp — the e-class counterpart.
  • sreturn list / sreturn string name = "text" — the s-class counterpart.

AURA keeps a small archive of recent result sets, so r(summarize, mean) or e(regress, N) can reach a specific earlier command, not only the latest one.

Building a matrix from variables — mkmat

mkmat varlist [, options] builds a matrix from the columns of a variable list — the inverse of svmat, which writes a matrix back into variables.

Mixed containers — omatrix

An omatrix is a labelled 2-D table that may hold a mix of numbers and strings (rows x columns), meant for transport rather than algebra:

omatrix T = data(name age wage)
omatrix list T

18. Missing Values

A missing value means unknown, and AURA carries that through consistently — including in comparisons, where several other packages do not.

  • Calculations propagate missing. gen y = x*2 is missing wherever x is missing — "missing in, missing out".
  • Comparisons propagate missing (missing is NOT +∞). gen flag = (x<0) is missing where x is missing — not 0 and not 1, because the relation is unknown. This is the deliberate departure: it avoids the classic trap in packages where . ranks as the largest number, so that x > 1000 silently counts the rows where x is unknown. A comparison with . itself has no answer either: 5 < . is missing, and x < . is refused (write !missing(x)).
  • if excludes missing. A row whose condition is missing is dropped: summarize x if x>1000 ignores observations with missing x.
  • Summaries ignore missing. summarize reports the count it actually used.

Test for missing explicitly with missing() / mi(), or the . literal:

gen m = missing(x)            // 1 where x is missing
gen keep = 1 if !missing(x)   // ! is logical not
gen a = 1 if x==.             // x==.  is rewritten to missing(x)
gen b = 1 if x!=.             // x!=.  ->  !missing(x)

For matrices, data(x) keeps missing as NaN (so you see it); pull a clean sample explicitly with data(x, if(!missing(x))).

20. Tracing Execution

When you want to see exactly what AURA runs — to follow a script with loops and macros, or to watch a module — turn on tracing. These are set commands, so they work at the console and inside scripts alike.

set trace on — echo every command

set trace on
forvalues i = 1/3 {
    summarize x in 1/`i'
}
set trace off

With tracing on, AURA echoes each command as it runs, with its macros already expanded, prefixed with a - (distinct from the . of a command you typed). Loop and conditional headers are shown too (- forvalues i = 1/3 { … - }), so the structure of the program is visible, and the body is traced once per iteration with the real value of `i'. The trace is its own stream: it never mixes into stored results or the Problems panel.

set tracedepth N — limit the depth

set tracedepth N traces only down to call depth N. Commands that a module runs internally — an aura: block, a sub-command — count as one level deeper and are indented; loop iterations stay at the top level. Use it to keep the trace readable when a command calls into modules.

set tracedeep on — full Python traceback on a module error

set tracedeep on/off is a different setting: it controls how much detail you get when a .auru module raises an error. Off (the default), the error is a short, friendly message naming your module, the offending line, and which library raised it. On, it appends the full Python traceback — useful while developing a module.

set showcmd on/off Show the command lines in the Results window, or only the results

21. Getting Started with Demos

AURA ships with guided demos — small self-contained tutorials that load a sample dataset, open a step-by-step script in the editor, and let the user explore at their own pace. Each demo can be started in one click and undone in another.

How a demo works

  1. Start a demo from Help → Getting Started (or type demo start <name> at the prompt). Per-command demos (e.g. demo regress) run from the prompt, or from a command's own help page.
  2. AURA preserves your current workspace, then loads the demo's dataset(s) into the workspace and opens the demo script in the editor.
  3. A blue banner appears at the top with the title of the demo and a red End demo button.
  4. You run the script line by line (select a step, then F8 or Run selected) and watch the output in the Results window.
  5. When done, click End demo (or type demo end). Your previous workspace is restored exactly as it was.
