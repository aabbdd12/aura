Release notes

What changed in AURA

Additions and corrections in each release. The latest installer is always on the download page; earlier installers stay on GitHub.

AURA 1.2

Released 26/10/2026 Download 1.2 →

New

  • Python 3.15. AURA now runs on Python 3.15.2, supported until October 2031 (1.1 used Python 3.13, supported until October 2029), and its windows on Tcl/Tk 9.0.4. pandas, NumPy, SciPy, statsmodels, linearmodels, matplotlib, Plotly and Qt keep the versions of 1.1.
  • Commands and results do not change: the examples of the help pages give the same output as in 1.1.

For developers

  • Running AURA from source needs Python 3.15; pip install -r requirements-lock.txt installs the library versions AURA is built and tested with (the User Guide said Python 3.10 or later).

AURA 1.1

Released 26/10/2026 Download 1.1 →

New

  • Edit a graph where it is. Each 2-D graph window has a Start Graph Editor button: the window gives way to the graph’s editor, at the same place and size; close the editor and the edited graph comes back in its window. Each window keeps its own graph, on the data it was drawn from, whatever changes in the dataset afterwards. graph save writes the current graph with its edits, and clear all closes every graph. Edited graphs keep AURA’s look (light grid, open frame).
  • Help examples that build on each other. Clicking an example first replays, silently, the examples above it in its group, so predict after logit or restore after preserve works on its own; a py: block or a forvalues loop runs as a whole. The replay never runs a command that touches your files or the system. 51 more help pages now carry sample data, so their examples can be run.
  • Faster start-up: the window is ready in about 2.4 s (3.4 s for 1.02 on the same machine). The statistical and graphics libraries are loaded when they are first needed, so the first estimation of a session takes about a second longer.
  • Updated foundations: Python 3.13.17; pandas 3.1, NumPy 2.5, SciPy 1.18, statsmodels 0.15, linearmodels 7.1, matplotlib 3.11, Plotly 7.1, Qt 6.12 (PySide6, with Chromium 140 for the 3-D viewer).

Corrected

  • ivregress: the Durbin test of endogeneity was computed with a first stage on the excluded instruments only; it now uses all the instruments.
  • DAAP ipov with a poverty line derived from the distribution (opl()): the standard errors left out the variability of the estimated line; they now include it and equal DASP’s. bip: the standard errors use the exact derivative with respect to the boundary. DAAP now computes in double precision throughout, so a single-precision weight (as stored in some .dta files) no longer changes the results.
  • Conditions: with count, summarize, keep, drop, list and many other commands, if x != 0 counted the observations where x is missing, and missing(x), !missing(x), x == . or a scalar in the condition failed. Every command now reads its condition as generate does: a missing result leaves the observation out. drop if missing(x) and drop in a/b now work, and recode honours in.
  • Text in commands: a quoted text containing in or if (gen a = "come in 2 days") was read as a qualifier — only observation 2 was filled, without an error; several spaces in a text were merged; !, ^ or == . inside a text were rewritten ("Hi!" was stored as Hi~). Texts are now kept as written.
  • substr(), word(), strpos(), subinstr(), abbrev(), regexm() and regexr() accept arguments that vary by observation, such as substr(email, strpos(email, "@") + 1, 99); substr() without a length runs to the end of the text.
  • quietly and capture in front of local now work, and commands that read their own text (timer, note, set…) no longer see these prefixes.
  • Exported .dta files open in Stata SE and BE: they were written in format 119, which only Stata/MP reads. File → Export → Stata asks for a file name (it wrote stata.dta without asking).
  • The 3-D viewer ended with a crash each time its window was closed (Windows recorded an application error); it now closes cleanly, and a 3-D graph drawn just after closing it no longer needs a second click.
  • Windows: a graph drawn from a help example now opens in front of the help window (it opened behind it); Help → About no longer opens a second window when asked again; the start-up screen no longer jumps to another size and place while AURA loads.
Behaviour changes:
  • in counts the observations of the whole dataset, before if: list x if region == 1 in 1/100 lists the observations of region 1 among the first 100 (it listed the first 100 observations of region 1).
  • One rule for the type of a variable in replace, generate … if and recode: numbers widen (an integer variable that receives 1.5 becomes decimal), true/false values become 0/1, and text and numbers do not mix — such a command is refused with a type mismatch error, where it used to create a column mixing both. The text targets of recode are stored without their quotes.
  • CSV import reads decimal numbers exactly: a file holding 0.30000000000000004 gives that value, not 0.3.

AURA 1.02

Released 21/10/2026 Download 1.02 →

New

  • Help → Check for Updates… (also in Help → About) tells you whether a newer AURA is available and offers to open its download page. AURA contacts GitHub only when you click; nothing is downloaded or installed automatically.

Corrected

  • summarize with a weight: the standard deviation is now reported; the stored results r() are the weighted values shown in the table (they were unweighted); detail now honours the weight (it was ignored). r(sum_w) is always stored, and with detail also r(p1)…r(p99), r(skewness) and r(kurtosis). The formulas for each weight type are in help summarize; frequency weights give the results of the data with each row repeated.
  • egen pctile() accepted a weight and ignored it; the weight is now applied.
  • collapse and egen: weighted standard deviations, variances and percentiles follow the same conventions as summarize (a frequency-weighted standard deviation now equals that of the repeated data).
  • Weights that cannot be used are refused with a message: negative frequency or analytic weights, non-integer frequency weights.
  • Tables: two-way tabulate (its row, column and cell percentages now carry totals), describe, range and compare use the same table layout as the rest of AURA, and codebook, svydes, inspect and help draw continuous rules. Survey tables (svy:) no longer show a stray blank header line.
  • DAAP: the t column is shown with 4 decimals, and the “Statistical Inferences” block of test() is drawn like the tables above it.

Behaviour change: the percentiles of summarize, detail now come from the empirical distribution (with 20 observations, the 1% percentile is the smallest value, without interpolation), and the skewness and kurtosis are the moment ratios, without small-sample correction; the kurtosis equals 3 for a normal distribution (it was the excess kurtosis). The percentiles of egen pctile(), egen iqr() and collapse (p#) use the same definition; medians do not change.

AURA 1.01

Released 20/10/2026 Download 1.01 →

New

  • Survey bootstrap. bootstrap gains method(raowu|naive|bayes) and a svy option: PSUs are drawn within the strata of svyset and each replicate is carried by the sampling weight. Rao–Wu is the default, so standard errors stay right even with few PSUs per stratum; a calibrated Bayesian bootstrap is also available. A command that ignores the sampling weight is refused instead of giving a wrong standard error.
  • Easier reading in the help and the guides: spaced paragraphs, a comfortable line width and aligned lists. Commands in the guides are clickable and open their help in a new tab.
  • Help → About now shows the release date.

Faster

  • hidja bootstrap standard errors: about 30× faster (200 replications on 8,478 households: 2 min 40 s → about 5 s).
  • Exact kernel density (ipola der/ip, dpolas, dpolag, dipola): 15–27× faster, and no longer slows down quadratically with the sample size.
  • 3-D graphs open much faster, and the viewer comes to the front for each new graph.

Corrected

  • hidja and ipola egr: the design bootstrap now uses Rao–Wu. The previous scheme understated standard errors when strata have few PSUs (by up to 29% with 2 PSUs per stratum). ipola egr follows set seed.
  • dtcpov (Jalan–Ravallion): the bootstrap bias correction now reports standard errors; the standard error of the analytically corrected chronic component uses its own household values; the Bias row has one sign convention (naive − corrected).
  • hidja: t and P>|t| are shown for the decomposition components only.
  • bootstrap errors now reach the script editor’s Problems panel and the log.
  • cprogtb help, example 3: it drew one curve per value of net income.
  • Help window: the redundant Help menu was removed and the menu shortcuts are aligned.
  • Installing over an earlier version now removes the program files that version no longer ships (a retired command stayed usable). Your settings, scripts and packages in ~/AURA are kept.

Behaviour change: the default bootstrap method is now Rao–Wu. Use method(naive) to reproduce results from AURA 1.00.
